# Flow authoring: layout

Status: decision, 2026-10-22 (Mike); "kept tight" added 2026-10-23 (Mike). Rule in `AGENTS.md`; the tools are
`thingstudio-compile --layout` / `--relayout` (and the older `test-flows/relayout.py`); the check is
`editor/test/flow-layout.test.ts`.

## The rule

A flow this project authors — `test-flows/*.flow.json`, an example shipped with the docs, anything generated for
someone to open — is laid out **left to right**: sources at the left edge, every wire running to a node further
right, branches stacked vertically inside their column.

Mike, looking at the reworked `gui-hero-cyd` flow: "flows generated by you should generally flow left to right,
otherwise they look like a rats nest." The graph was fine in every one of them; the layout restarted at x=80 on
each second row, so a reader had to follow a wire backwards to work out where the chain continued.

## Why it is a rule and not a preference

The canvas is the whole representation of a flow. Nothing in the file format needs a particular order — nodes and
edges are independent of position — so layout is pure presentation, and presentation is the only thing a reader has.
A backwards wire costs a re-read every time someone opens the file; laying out along the data direction costs
nothing at generation time.

It also makes a difference that survives the canvas: a left-to-right layout is what a screenshot, a docs page, or a
reviewer's mental model of the flow looks like. The hero flows are the ones people see first.

## How it is kept

- `python3 test-flows/relayout.py <flow.json>` rewrites the layout: column = longest distance from a source, row =
  position within the column (ordered by where a node's predecessors sit, so a branch stays beside what feeds it).
  Output positions only; nodes, edges, configs, panes and screens are untouched (`ensure_ascii=False`, so a diff
  shows positions and nothing else).
- `--check` reports wires that go left or straight down, for a quick look without rewriting.
- `editor/test/flow-layout.test.ts` runs the same check over every `test-flows/*.flow.json` in `npm test`, so a new
  or regenerated flow that wraps fails CI rather than being noticed on the canvas. It also fails a flow with a node
  that has no layout position at all (those stack at the origin in the editor).

## What it does not cover

- **A user's own flows.** The editor never repositions nodes on load or save; a flow someone arranged their own way
  stays that way. This is an authoring rule for what we hand out, not a canvas feature.
- **Automatic layout in the editor.** There is none, and this does not add one. If a "tidy up" button is ever wanted,
  it is an editor feature with its own decision; `relayout.py` shows what the layout rule would be.
- **Vertical order** is only "stacked within the column, near what feeds it" — not an aesthetic ordering. A flow with
  many branches may still be tall; that is allowed, since the cost the rule is about is leftward wires.

## History

2026-10-22: hero flows (CYD, CYD dummy, three Freenove variants) plus `gui-touch-*` and `udp-echo-tester` relaid out
by the tool; the two latter ones had leftward wires and no other change.

## 2026-10-23: kept tight, and checked by the compile command

Mike, on the AI-authoring skill: it "needs to include some rules/guidance on the layout of flows eg: generally left
to right, kept fairly visually tight". The rules are now written once, in `docs/user-guide/ai-authoring.md#layout`,
and the skill repeats them.

The numbers come from the flows Mike laid out by hand in the editor (`kitchen-sink`, `bmp280-test-flow`,
`basic-mqtt`), not from `relayout.py`'s grid: columns about 220 px apart, about 36 px between nodes stacked in a
column, about 66 px between separate chains. Nodes are 34 px tall and 84-132 px wide, so `relayout.py`'s 170 px row
pitch left about 136 px of empty space between rows, looser than anything Mike laid out himself.

- `thingstudio-compile --layout` (`editor/src/cli/layout.ts`) reports, as `layout:` warnings: nodes with no
  position, wires that go backwards or have no room, overlapping nodes, empty bands more than 200 px across or 150 px
  down, a flow that starts more than 320 px from the origin (the editor does not fit the view on open), and wires a
  few pixels out of line. The warning thresholds are looser than the target, so a flow laid out by hand in roughly
  the right shape passes. It is opt-in, so a user's own flow is never judged unless someone asks.
- `--relayout` lays a flow out per chain (each weakly connected group on its own, stacked), column = longest path
  from a source, y = average of the feeding nodes pushed down only to clear the node above, so a straight chain is one
  straight row. Every shipped flow relaid out passes `--layout` (`editor/test/cli-layout.test.ts`).
- Relaid out on 2026-10-23 because the skill ships them as examples and the skill build refuses an example that fails
  `--layout`: `basic-http-request`, `bmp280-test-flow` (positions only), and
  `ai-authoring/climate-two-page-modal-freenove` (four wires ran backwards).
- `editor/test/flow-layout.test.ts` still checks only direction for `test-flows/`. Other shipped flows (the hero
  flows on the 260 x 170 grid, the display tests at 300 px pitch) pass that test but would draw `--layout`
  warnings; they were left alone.
