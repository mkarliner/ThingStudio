# HELLO frozenDependencies — briefing

Status: handoff, 2026-11-13. Work in progress, **uncommitted** in the working tree on `remote-display-spike`.
Mike approved the protocol change in-session ("Yes, add it", 2026-11-13).

## Why

On 2026-11-13 the S3 on custom image `8790056` served the pre-fix remote page. The flash had worked, but a
deploy from an out-of-date checkout had pushed an older `ts_remote` into `/lib`. Since runtime 11.1.0, `/lib`
loads before frozen modules, so the stale copy ran in place of the image's own, and nothing said so. HELLO's
`dependencies` lists only the copy that wins. The incident is in `learnings/firmware-builds.md` (2026-11-13).

Mike's rule ("you should get a warning"), recorded in `decisions/custom-firmware.md` (2026-11-13): a deploy that
puts a library over the image's own copy **warns, not refuses**.

## What's done (uncommitted)

- **Interface** (`interfaces/protocol/`): HELLO gains optional `frozenDependencies` (map string→string), the
  image's frozen inventory. SPEC.md: a table row plus a paragraph under HELLO. `messages.json`: the HELLO
  summary. Vectors: HELLO-0 gets `frozenDependencies: null`, and HELLO-1 gets `{"mqtt_as": "fedcba9876543210"}`
  with `frameHex` regenerated by the editor codec (421 → 466 bytes).
- **Board**:
  - `deps.frozen_inventory()` returns the image's inventory, or `None` on stock firmware.
  - `listener.py` sends it in HELLO.
  - `messages.py` decodes it.
  - Runtime bumped to **16.1.0** (minor: an optional field, no codegen change), with `EDITOR_TARGET_VERSION` in
    `editor/src/app/main.ts` bumped to match.
- **Editor**:
  - `flow-dependencies.ts` has two new functions: `shadowedFrozenLibraries()` and `sendsOverFrozen()`.
  - `main.ts` warns on HELLO when a `/lib` copy runs instead of the image's, and warns before a deploy sends
    a library the image already has.
  - The HELLO test fixtures carry the new field.
- **CLI**: `test-flows/device_cli.py` prints the same warning after HELLO and on deploy.
  `test/hil/hil_common.py` takes `frozen=` and warns before sending.
- **Tests**:
  - `test_deps.py` has two new tests.
  - The `minitest.run` list moved to the end of `test_deps.py`, so its two old frozen tests now run. One of them
    had never run and had a fixture bug (it named `mqtt_as.mpy` in the index without creating the file);
    the fixture is fixed.
  - `test_protocol.py`'s HELLO samples carry the field.
