## Implemented 2026-09-02, not yet verified by Mike on real hardware

Built for real this time, full scope per Mike's own decision (AskUserQuestion answers: build the complete feature, but explicitly exclude the `startup` node -- see `init-node-on-flow-start.md` -- and drop inject's periodic repeat options entirely rather than keep them alongside click-fire):

- New §13 `TRIGGER` message (byte 9), editor -> device, `{nodeId}`, fire-and-forget -- `editor/src/protocol/messages.ts`/`codec.ts`, mirrored in `device-runtime/src/messages.py`.
- `inject.ts` rewritten from `codegenSource`(repeatMs) onto `codegenEventSource`, same pattern `interrupt.ts` established: a `ThreadSafeEvent` per instance, self-registered with `runtime.register_trigger(nodeId, evt)` at setup time. The `repeat` property (`manual`/`1s`/`5s`/`30s`) is gone entirely -- no periodic option survives, inject fires only on a real TRIGGER.
- `device-runtime/src/runtime.py`: new `_triggers` registry (`register_trigger`/`fire_trigger`), cleared in `cancel_running()` on redeploy, mirroring `register_cleanup`'s existing shape.
- `device-runtime/src/listener.py`: `_dispatch()` calls `runtime.fire_trigger(msg["nodeId"])` on an incoming TRIGGER; an unknown/stale nodeId degrades to a logged no-op, not an error.
- Editor UI: clicking an inject node on the canvas while live-connected sends TRIGGER (`editor-setup.ts`'s `onNodeClicked` hook, wired in `main.ts`); `PropertyPanel.vue`'s repeat dropdown is gone, replaced with a one-line hint.
- Tests: new `editor/test/node-inject.test.ts` (codegen shape, full-flow structure, end-to-end run); `device-runtime/test/test_runtime.py` and `test_listener_integration.py` extended for the trigger registry and the real TRIGGER dispatch path; `protocol.roundtrip.test.ts`/`test_protocol.py` extended for TRIGGER's CBOR round-trip. The pymock CPython test fixture (`editor/test/fixtures/pymock/runtime.py`/`threadsafe_event.py`) needed real changes too, since inject is now an always-looping event-source node like `interrupt`/`timer`/`wifi_status` rather than a one-shot -- see that fixture's own updated header for the CPython-3.9 `asyncio.Event` loop-binding hazard this surfaced (same class of bug already fixed once this session in `mqtt-shared.ts`) and the generic "auto-fire every registered trigger shortly after start, bounded run" mechanism that keeps the ~15 existing downstream-node tests using inject as their message source passing unmodified.

**Not yet verified**: the real click -> WebSerial -> TRIGGER -> device round trip has not been tried on real hardware. `basicmqtt.flow.json` (the flow that originally surfaced this gap via a silent-failure hardware test) is the natural first real-world check once Mike redeploys with this build.
